# Personalize

This repository was sanitized before publication. Wherever a real name, path, key, or host used to be, there is now a placeholder. Nothing here will work until you replace them.

## Placeholder reference

| Placeholder | Replace with | Where it appears |
| --- | --- | --- |
| `the owner` | Your name, or leave as-is | Agent prompts, charters, policies |
| `<you>` | Your OS username | Paths like `C:\Users\<you>`, `/Users/<you>` |
| `you@example.com` | Your email | Cloud-drive mount paths |
| `<vault>` | Your knowledge-vault root | Documentation-write targets in prompts |
| `<cloud-drive>` | Your synced drive root, if you use one | Migration and deployment runbooks |
| `mac-host`, `win-workstation` | Your hostnames | Validation records |
| `<tailnet>`, `<gateway-ip>`, `<host-ip>`, `<subnet>`, `<iface>`, `<port>` | Neutral examples only; do not publish live network values | Validation and operations records |
| `<os-version>`, `<os-build>`, `<kernel-build>`, `<hw-model>`, `<cpu-model>`, `<memory-size>`, `<tool-version>` | Generic host/software fingerprints | Validation records |
| `<event-id>`, `<channel-uuid>`, `<team-id>`, `<persona-id>` | Generated by Buzz at runtime | Validation records, squads |

Find them all:

```bash
grep -rnoE '<(you|vault|cloud-drive|event-id|channel-uuid|team-id|persona-id)>' . | sort -u
```

> [!warning] Do not add identity keys to setup documentation
> Buzz generates identity material during deployment. Keep key handling in the encrypted backup-and-recovery process, not in rosters, prompts, squad descriptions, or validation notes.

## "The owner" in agent prompts

Every persona prompt in [`agents/platform-agents/`](../agents/platform-agents/) says things like:

> You are **Lin SRE**, the owner's SRE specialist in the **Infrastructure Squad**.

You can leave `the owner` exactly as written — Buzz has a real owner concept, and `owner-only` response mode maps onto it. Substituting your own name is purely cosmetic. What is **not** cosmetic:

- The vault path the prompt tells the agent to read and write.
- The repository roots the prompt scopes the agent to (`~/Git` by default).
- The cloud environments named as in-scope (test only, by default).

Fix those three before deploying, in every prompt you use.

## Scope boundaries to review

The [Shared Operating Contract](../agents/01-shared-operating-contract.md) and each platform prompt encode a specific standing scope:

| Boundary | Default in this repository | Check |
| --- | --- | --- |
| Repositories | Explicitly assigned repos under `/Users/<you>/Git` on macOS or `C:\Users\<you>\Git` on Windows | Does the platform-appropriate path exist? |
| Documentation | The owner's personal knowledge vault | Point it at yours, or remove the instruction |
| Cloud | Explicitly assigned **test** Azure/AWS only | Never widen this to production casually |
| Production | Out of scope unless explicitly changed per task | Leave it out of scope |

## Suggested order

1. Read [SECURITY.md](../SECURITY.md) first. All of it.
2. Read [Approval Gates and Change Safety](../agents/02-approval-gates-and-change-safety.md) and decide whether its gates match your risk tolerance. Tighten, don't loosen.
3. Pick **one** persona from [`agents/platform-agents/`](../agents/platform-agents/) and personalize only that one.
4. Deploy it with autostart **disabled** and `parallelism: 1`.
5. Run the acceptance tests in the [Creation and Validation Runbook](../agents/05-creation-and-validation-runbook.md).
6. Record the result. Then do the next one.

The [validation template](../agents/validation-record-template.md) shows how to record step 5 without publishing host posture, private paths, or exact toolchain fingerprints.

## What you should not copy blindly

- **The runtime assignments** in [07 - Runtime and LLM Assignment Matrix](../agents/07-runtime-and-llm-assignment-matrix.md) reflect one machine's hardware, one set of local models, and one account's quota. Your tiers will differ.
- **The 51-agent roster** is a menu, not a target. Most people need three or four agents. Deploying all 51 because they exist is how you get a large bill and no working system.
- **The autostart settings.** Everything in this repository was built with autostart disabled first, for good reason.
